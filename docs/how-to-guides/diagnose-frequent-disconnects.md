# 자꾸 끊기는 연결 진단하기

VPN이 연결되었다가 몇 분~몇십 분 만에 자꾸 끊기고 자동 재연결이 반복된다면, 아래 순서로 원인을 좁혀볼 수 있습니다.

## 1. 로그 파일 열기

```bash
tail -f logs/fortiautoconn.log
```

끊길 때마다 아래와 같은 로그가 남습니다.

```
연결 수명 감시 실패 감지 (1/3회 연속) — 프로세스 생존: True, ppp 인터페이스(ppp0): 인터페이스 소멸(ifconfig 조회 실패)
...
VPN 터널 세션이 유실되었습니다 (연속 3회 실패, ...).
세션 종료 전후 openfortivpn/pppd 출력(최근 N줄):
...
```

`isalive()`(프로세스 생존)와 ppp 인터페이스 상태를 5초마다 같이 확인하는 이유는, `openfortivpn`을 감싼 `sudo` 래퍼는 살아있는데 그 안의 실제 터널(pppd)만 조용히 죽는 경우가 있기 때문입니다. 자세한 이유는 [아키텍처와 설계 결정](../explanation/architecture.md)을 참고하세요.

## 2. "세션 종료 전후 출력" 블록을 읽기

"VPN 터널 세션이 유실되었습니다" 로그 바로 뒤에, `openfortivpn`/`pppd`가 종료 직전에 실제로 남긴 출력이 함께 찍힙니다. 여기서 원인을 구분할 수 있습니다.

- **`Hangup (SIGHUP)` + `LCP close (User request).`** — pppd가 스스로 크래시한 게 아니라, `openfortivpn`이 SSL 터널 쪽 문제를 감지하고 pppd를 정리한 것입니다. 즉 게이트웨이(FortiGate) 쪽에서 세션이 끊긴 것에 가깝습니다.
- **`Gateway certificate validation failed`** — 사내 게이트웨이 인증서 문제입니다. 앱이 자동으로 해시를 감지해 재시도하므로 보통은 한 번 더 시도되고 지나갑니다. 반복되면 게이트웨이 인증서가 실제로 바뀐 것일 수 있습니다.
- **아무 출력도 없이 조용히 끊김** — 네트워크 자체(Wi-Fi, 회선)가 끊긴 경우일 가능성이 높습니다.

## 3. "얼마나 오래 붙어있었는지"와 "얼마나 트래픽이 오갔는지"를 같이 보기

캡처된 출력에 보통 아래 줄이 포함됩니다.

```
Connect time 5.0 minutes.
Sent 2083 bytes, received 2241 bytes.
```

**연결 유지 시간이 들쭉날쭉하고, 오간 바이트 수가 적을수록 더 빨리 끊기는 패턴**이라면, FortiGate가 "트래픽이 없으면 유휴로 간주해 세션을 끊는" 정책을 쓰고 있다는 뜻입니다. 이 앱은 이미 이런 상황을 완화하는 기능이 내장되어 있습니다 — 연결이 살아있는 동안 60초마다 ppp 터널 반대편으로 최소한의 핑을 흘려보내 유휴 상태처럼 보이지 않게 합니다(`VPNConnector.IDLE_KEEPALIVE_INTERVAL_SECONDS`). 그런데도 계속 짧게 끊긴다면:

- 사내 IT팀에 해당 시간대 FortiGate SSL-VPN 세션 로그(유휴 타임아웃 정책, 동시 세션 제한)를 확인해 달라고 요청하세요.
- `vpn_connector.py`의 `IDLE_KEEPALIVE_INTERVAL_SECONDS`(기본 60초) 값을 게이트웨이의 실제 유휴 타임아웃보다 충분히 짧게 줄여볼 수 있습니다.

## 4. 메일 쪽 지연도 같이 확인하기

VPN 연결 자체와는 별개로, 인증 메일(OTP) 조회가 느려서 연결 시도가 실패하는 경우도 있습니다. 로그에서 아래 경고를 찾아보세요.

```
SEARCH 응답이 느립니다: 12000ms, 매칭 15건 (status=OK)
```

이게 반복되면 메일 서버 응답이 느린 것이고, VPN 연결 자체의 문제가 아닙니다.

## 5. 더 자세한 로그가 필요하면

```bash
FORTI_DEBUG=1 ./run.sh
```

메일 폴링 타이밍 등 평소에는 숨겨진 DEBUG 레벨 로그까지 볼 수 있습니다.
